# 项目深度理解

## 1. 项目目标与价值

### 项目目标

这个项目解决的核心矛盾是：业务系统日益复杂（容器化/微服务化）与运维可观测能力滞后之间的矛盾。通过构建PLG监控栈，我们实现了Metrics+Logs的统一关联，将MTTR（平均修复时间）从小时级缩短到分钟级。

### 业务价值

业务价值体现在三个维度：稳定性（通过模拟故障测试验证，服务宕机1分钟内必告警）、效率（日志检索从grep遍历变为Loki秒查）、合规（满足等保2.0对审计日志6个月留存的要求）。直接支撑了业务的7×24小时连续性承诺。

### 技术价值

技术价值不仅是技术栈的广度（Docker+Prometheus+Loki+Grafana+Nginx全链路），更是工程化深度：1)通过基线采集建立性能基准，2)通过混沌测试验证告警可靠性，3)通过分层架构实现Metrics和Logs的关联分析。这体现了从'搭环境'到'建体系'的能力跃迁。
