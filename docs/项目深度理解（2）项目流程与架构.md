# 项目深度理解(2)项目流程与架构

## 项目目标

**核心目标**：解决业务系统日益复杂（容器化/微服务化）与运维可观测能力滞后之间的矛盾。通过构建PLG监控栈，实现Metrics+Logs的统一关联，将MTTR（平均修复时间）从小时级缩短到分钟级。

**验证标准**：
1. 实现Metrics（指标）和Logs（日志）的统一标签关联
2. 在Grafana中实现指标和日志的联动查询
3. 能够通过告警快速定位问题根因
4. 验证MTTR从小时级缩短到分钟级

### 技术选型理由

**Docker**：选择Docker作为容器化平台，理由如下：
- **稳定性**：成熟的容器技术，广泛应用于生产环境
- **社区支持**：拥有庞大的社区和丰富的镜像资源
- **学习成本**：入门门槛较低，文档完善
- **标准化**：提供一致的运行环境，简化部署和运维

**Prometheus**：选择Prometheus作为指标监控系统，理由如下：
- **稳定性**：CNCF毕业项目，稳定性得到验证
- **社区支持**：拥有丰富的exporter生态和集成方案
- **学习成本**：查询语言PromQL易于学习和使用
- **扩展性**：支持多种数据采集方式和告警规则配置

**Loki**：选择Loki作为日志系统，理由如下：
- **稳定性**：与Grafana无缝集成，性能稳定
- **社区支持**：由Grafana Labs维护，社区活跃
- **学习成本**：查询语法与PromQL相似，易于上手
- **存储效率**：采用索引模式，存储效率高，适合大规模日志

**Grafana**：选择Grafana作为可视化平台，理由如下：
- **稳定性**：成熟的可视化工具，广泛应用
- **社区支持**：拥有丰富的仪表盘模板和插件
- **学习成本**：直观的UI界面，易于配置和使用
- **集成能力**：支持多种数据源，实现Metrics和Logs的统一展示

**Alertmanager**：选择Alertmanager作为告警管理系统，理由如下：
- **稳定性**：Prometheus生态的核心组件，稳定可靠
- **社区支持**：与Prometheus无缝集成，文档完善
- **学习成本**：配置简单，易于理解和使用
- **告警管理**：支持告警分组、静默、抑制等高级功能

### 组件关系

**数据流向**：
1. **数据采集**：Node Exporter、cAdvisor、Promtail等exporter从基础设施和应用中采集指标和日志
2. **数据存储**：Prometheus存储指标数据，Loki存储日志数据
3. **告警处理**：Alertmanager接收Prometheus的告警，进行分组、去重和路由
4. **可视化展示**：Grafana从Prometheus和Loki读取数据，展示为仪表盘和日志查询界面
5. **统一访问**：Nginx作为统一入口，提供所有监控服务的访问路由

### PLG技术栈协同工作方式

#### 1. Prometheus数据采集与存储机制
**数据采集机制**：
- **Pull模式**：Prometheus采用Pull模式从exporters采集数据
- **Scrape配置**：通过prometheus.yml中的scrape_configs配置采集目标
- **采集间隔**：默认15秒，可通过scrape_interval配置
- **指标暴露**：exporters通过HTTP接口暴露指标数据（通常在/metrics端点）
- **标签体系**：使用统一的标签体系（instance、job等）标识指标来源

**存储机制**：
- **时序数据库**：采用自定义的时序数据库存储指标数据
- **数据格式**：使用时间序列格式，包含时间戳和数值
- **存储引擎**：基于TSDB（Time Series Database），支持高写入和查询性能
- **数据保留**：默认保留15天，可通过--storage.tsdb.retention.time配置
- **压缩策略**：采用分层压缩策略，提高查询性能和存储效率

#### 2. Loki日志采集与存储机制
**日志采集机制**：
- **Promtail采集**：使用Promtail作为日志采集器，支持多路径日志采集
- **标签索引**：只索引日志的标签，不索引日志内容，提高存储效率
- **日志推送**：Promtail将采集的日志推送到Loki
- **日志过滤**：支持基于标签的日志过滤和查询

**存储机制**：
- **索引存储**：使用索引存储标签信息，提高查询效率
- **日志存储**：将日志内容存储为压缩块，减少存储开销
- **查询模式**：支持基于标签和正则表达式的日志查询
- **存储后端**：支持本地文件系统、对象存储等多种存储后端

#### 3. Grafana可视化与联动机制
**仪表盘配置**：
- **数据源管理**：支持配置多个Prometheus和Loki数据源
- **面板类型**：支持图表、表格、文本等多种面板类型
- **查询编辑器**：提供PromQL和LogQL查询编辑器
- **变量配置**：支持创建变量实现动态查询和联动
- **模板化**：支持仪表盘模板化，便于复用和扩展

**联动查询机制**：
- **标签关联**：通过统一的标签体系实现指标和日志的关联
- **变量联动**：使用Grafana变量实现仪表盘间的联动
- **跳转链接**：配置从指标面板跳转到日志查询的链接
- **上下文传递**：支持将指标查询的上下文传递到日志查询

#### 4. Alertmanager告警管理机制
**告警规则评估**：
- **规则文件**：通过rules目录下的YAML文件定义告警规则
- **评估间隔**：默认15秒，可通过evaluation_interval配置
- **告警触发**：当指标超过阈值时触发告警
- **告警状态**：支持Pending、Firing等状态

**告警管理**：
- **告警分组**：按alertname、severity、instance等维度分组
- **告警去重**：避免重复告警
- **告警静默**：支持基于时间和标签的告警静默
- **告警抑制**：支持高级别的告警抑制低级别的告警

**告警通知**：
- **通知渠道**：支持Email、Slack、Webhook等多种通知渠道
- **通知模板**：支持自定义通知模板
- **重试机制**：支持告警通知的重试机制

### 全链路监控流程

#### 1. 数据采集流程
1. **指标采集**：Node Exporter和cAdvisor通过HTTP接口暴露指标
2. **Prometheus抓取**：Prometheus定期从exporters抓取指标数据
3. **数据存储**：将指标数据存储到TSDB中
4. **日志采集**：Promtail采集系统和应用日志，推送到Loki
5. **日志存储**：Loki建立索引并存储日志数据

#### 2. 告警处理流程
1. **规则评估**：Prometheus根据告警规则评估指标数据
2. **告警触发**：当指标超过阈值时，触发告警并发送到Alertmanager
3. **告警管理**：Alertmanager对告警进行分组、去重和路由
4. **格式转换**：prometheus-webhook-dingtalk将告警转换为钉钉格式
5. **通知发送**：将告警通知发送到钉钉群

#### 3. 故障排查流程
1. **告警接收**：运维人员通过钉钉接收告警通知
2. **仪表盘查看**：通过告警中的跳转链接进入Grafana仪表盘
3. **指标分析**：查看相关指标的趋势和异常
4. **日志查询**：通过联动查询查看相关日志
5. **问题定位**：结合指标和日志，定位故障根因
6. **问题解决**：实施解决方案，恢复服务

#### 4. 可视化展示流程
1. **数据源配置**：在Grafana中配置Prometheus和Loki数据源
2. **仪表盘创建**：创建指标和日志仪表盘
3. **查询配置**：配置PromQL和LogQL查询
4. **变量设置**：设置变量实现动态查询
5. **联动配置**：配置指标和日志的联动查询
6. **权限管理**：配置用户权限，控制访问
