# 项目深度理解(3)核心模块拆分

## 1. 功能模块

### 1.1 采集层模块
- **Node Exporter**：主机级指标采集模块，负责采集服务器的CPU、内存、磁盘、网络等系统指标
- **cAdvisor**：容器级指标采集模块，负责采集Docker容器的资源使用情况和性能指标
- **Promtail**：日志采集模块，负责采集系统日志、容器日志和应用日志，发送到Loki进行存储和查询

### 1.2 存储层模块
- **Prometheus**：时序数据库模块，负责存储和查询指标数据，支持高基数指标和复杂查询
- **Loki**：日志存储模块，负责存储和查询日志数据，采用索引模式提高查询效率

### 1.3 告警层模块
- **Alertmanager**：告警管理模块，负责接收Prometheus的告警，进行分组、去重、静默和路由
  - **告警分组**：按alertname、severity、instance等维度对告警进行分组
  - **告警去重**：避免重复告警，减少告警风暴
  - **告警静默**：支持基于时间和标签的告警静默
  - **告警抑制**：支持高级别的告警抑制低级别的告警
  - **告警路由**：根据告警标签将告警路由到不同的通知渠道
- **prometheus-webhook-dingtalk**：告警通知模块，负责将Alertmanager的告警转换为钉钉兼容的格式，发送到钉钉群
  - **格式转换**：将Alertmanager的告警格式转换为钉钉消息格式
  - **模板配置**：支持自定义告警通知模板
  - **链接跳转**：在告警通知中添加Grafana仪表盘的跳转链接

### 1.4 可视化层模块
- **Grafana**：可视化展示模块，负责创建仪表盘，展示指标数据和日志数据，支持联动查询
  - **数据源管理**：配置Prometheus和Loki作为数据源
  - **仪表盘创建**：创建主机监控、容器监控、应用监控等仪表盘
  - **查询配置**：使用PromQL查询指标数据，使用LogQL查询日志数据
  - **变量配置**：创建instance、job等变量，实现动态查询
  - **告警配置**：配置仪表盘告警规则，支持阈值告警和趋势告警
  - **联动查询**：实现指标和日志的联动查询，支持从指标跳转到日志

### 1.5 接入层模块
- **Nginx**：统一访问入口模块，负责反向代理所有监控服务，提高安全性和易用性

### 1.6 运维工具模块
- **baseline.sh**：基线采集模块，负责采集服务器的配置、性能、安全基线数据
- **server-init.sh**：服务器初始化模块，负责服务器的初始化和安全加固
- **install-docker-openeuler.sh**：Docker环境安装模块，负责安装和配置Docker环境

## 2. 关键流程

### 2.1 监控数据采集流程
1. **指标采集**：Node Exporter和cAdvisor采集系统和容器指标，通过HTTP接口暴露
2. **数据抓取**：Prometheus定期从各exporter抓取指标数据
3. **数据存储**：Prometheus将指标数据存储到时序数据库中
4. **日志采集**：Promtail采集系统和容器日志，发送到Loki
5. **日志存储**：Loki将日志数据存储并建立索引

### 2.2 告警处理流程
1. **告警规则评估**：Prometheus根据配置的告警规则评估指标数据
2. **告警触发**：当指标超过阈值时，触发告警并发送到Alertmanager
3. **告警管理**：Alertmanager对告警进行分组、去重、静默和路由
4. **告警通知**：Alertmanager将告警发送到prometheus-webhook-dingtalk
5. **钉钉通知**：prometheus-webhook-dingtalk将告警转换为钉钉格式并发送到钉钉群

### 2.3 可视化查询流程
1. **数据源配置**：Grafana配置Prometheus和Loki作为数据源
2. **仪表盘创建**：在Grafana中创建指标和日志仪表盘
3. **数据查询**：Grafana从Prometheus查询指标数据，从Loki查询日志数据
4. **联动查询**：通过统一的标签体系，实现指标和日志的联动查询

### 2.4 故障排查流程
1. **告警触发**：系统异常触发告警，发送到钉钉群
2. **告警查看**：运维人员查看钉钉告警信息，获取告警详情和跳转链接
3. **仪表盘查看**：通过跳转链接进入Grafana仪表盘，查看指标数据
4. **日志查询**：通过联动查询，从仪表盘直接跳转到Loki日志查询
5. **问题定位**：结合指标和日志，快速定位故障根因
6. **问题解决**：实施解决方案，恢复系统正常运行

## 3. 技术难点

### 3.1 采集层技术难点
- **高基数指标处理**：处理大量标签导致的高基数问题，避免Prometheus性能下降
- **日志采集效率**：高效采集和传输日志数据，减少对业务系统的性能影响
- **数据一致性**：确保指标和日志使用相同的标签体系，实现统一关联

### 3.2 存储层技术难点
- **存储容量管理**：合理配置数据保留策略，避免存储溢出
- **查询性能优化**：优化Prometheus和Loki的查询性能，提高查询响应速度
- **数据压缩**：采用高效的数据压缩算法，减少存储占用

### 3.3 告警层技术难点
- **告警风暴避免**：通过告警分组、抑制和静默机制，避免大量告警同时触发
- **告警准确性**：优化告警规则，减少误报和漏报
- **告警格式兼容**：解决Alertmanager与钉钉的格式不兼容问题

### 3.4 可视化层技术难点
- **仪表盘性能**：优化Grafana仪表盘的加载性能，减少查询时间
- **联动查询实现**：实现指标和日志的无缝联动查询，提高故障排查效率
- **自定义可视化**：根据业务需求，创建自定义的可视化图表

### 3.5 接入层技术难点
- **安全访问控制**：配置Nginx的访问控制和认证机制，提高系统安全性
- **负载均衡**：在大规模部署时，实现监控服务的负载均衡
- **HTTPS配置**：配置HTTPS，确保数据传输的安全性

### 3.6 运维工具技术难点
- **自动化部署**：实现监控系统的自动化部署和配置
- **配置管理**：集中管理所有配置文件，便于维护和更新
- **备份恢复**：实现监控数据和配置的备份和恢复机制

## 4. 技术难点解决方案

### 4.1 采集层解决方案
- **指标过滤**：在exporter端过滤不必要的指标和标签，减少高基数问题
- **日志压缩**：采用gzip压缩日志数据，减少网络传输和存储开销
- **统一标签规范**：制定统一的标签命名规范，确保指标和日志使用相同的标签

### 4.2 存储层解决方案
- **数据分片**：采用Prometheus联邦集群或Thanos实现数据分片存储
- **索引优化**：优化Loki的索引配置，提高日志查询性能
- **存储清理**：配置合理的数据保留策略，定期清理过期数据

### 4.3 告警层解决方案
- **告警分组**：按alertname、severity、instance等维度对告警进行分组
- **告警抑制**：配置critical级别告警抑制warning级别告警，避免告警风暴
- **webhook适配器**：使用prometheus-webhook-dingtalk适配器，解决格式兼容问题

### 4.4 可视化层解决方案
- **查询缓存**：启用Grafana的查询缓存，提高仪表盘加载速度
- **变量联动**：使用Grafana变量实现指标和日志的联动查询
- **自定义插件**：开发自定义的Grafana插件，满足特定的可视化需求

### 4.5 接入层解决方案
- **basic auth**：配置Nginx的basic auth认证，限制访问权限
- **SSL证书**：配置HTTPS，使用Let's Encrypt获取免费证书
- **访问日志**：配置Nginx的访问日志，记录访问情况

### 4.6 运维工具解决方案
- **Ansible自动化**：使用Ansible实现监控系统的自动化部署
- **Git版本控制**：使用Git管理所有配置文件，便于版本控制和回滚
- **定期备份**：配置定期备份脚本，备份Prometheus和Loki的数据
