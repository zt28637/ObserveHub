# 项目深度理解(1)项目目标与价值

## 项目目标验证

### 核心目标
解决业务系统日益复杂（容器化/微服务化）与运维可观测能力滞后之间的矛盾。通过构建PLG监控栈，实现Metrics+Logs的统一关联，将MTTR（平均修复时间）从小时级缩短到分钟级。

### 验证标准
1. 实现Metrics（指标）和Logs（日志）的统一标签关联
2. 在Grafana中实现指标和日志的联动查询
3. 能够通过告警快速定位问题根因
4. 验证MTTR从小时级缩短到分钟级

### 验证结果

#### 5.基线采集指标

**概述**：基线采集指标是监控系统的基础数据，用于建立系统正常运行状态的基准，为异常检测和性能优化提供参考依据。以下是基线采集脚本采集的关键指标清单。

##### 5.1 系统配置指标

| 指标名称 | 描述 | 采集命令 | 单位 |
|---------|------|---------|------|
| 主机名 | 系统主机名 | `hostname -f` | - |
| 系统版本 | 操作系统版本 | `grep "^PRETTY_NAME" /etc/os-release \| cut -d '"' -f2` | - |
| 内核版本 | Linux内核版本 | `uname -r` | - |
| 系统架构 | CPU架构类型 | `uname -m` | - |

##### 5.2 CPU性能指标

| 指标名称 | 描述 | 采集命令 | 单位 |

##### 5.8 系统健康指标

| 指标名称 | 描述 | 计算方法 | 单位 |
|---------|------|---------|------|
| 健康分数 | 系统综合健康评分 | 基础分100分，根据各指标扣减 | 分（0-100） |
| 健康等级 | 系统健康等级评定 | 根据健康分数划分（优秀/良好/一般/较差） | - |
| 系统瓶颈 | 系统性能瓶颈识别 | 根据各指标阈值判断 | - |

**健康等级划分标准**：
- 优秀：健康分数 ≥ 90分
- 良好：健康分数 ≥ 70分且 < 90分
- 一般：健康分数 ≥ 50分且 < 70分
- 较差：健康分数 < 50分

**健康分扣减规则**：
- CPU使用率超过阈值（80%）：扣10分
- 内存使用率超过阈值（80%）：扣10分
- 磁盘使用率超过阈值（80%）：每个挂载点扣5分
- IO延迟超过阈值（100ms）：扣5分
