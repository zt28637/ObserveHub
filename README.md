# 全链路监控系统项目描述

## 一、项目背景

随着业务系统日益复杂（容器化/微服务化）与运维可观测能力滞后之间的矛盾日益突出，为解决这一痛点，本项目构建了基于PLG（Prometheus+Loki+Grafana）技术栈的全链路监控系统，实现Metrics+Logs的统一关联，将MTTR（平均修复时间）从小时级缩短到分钟级。

本项目采用容器化部署方式，结合自动化运维工具链，打造企业级一站式监控告警平台。

---

## 二、项目目标

### 核心目标
解决业务系统日益复杂（容器化/微服务化）与运维可观测能力滞后之间的矛盾。通过构建PLG监控栈，实现Metrics+Logs的统一关联，将MTTR（平均修复时间）从小时级缩短到分钟级。

### 验证标准
1. 实现Metrics（指标）和Logs（日志）的统一标签关联
2. 在Grafana中实现指标和日志的联动查询
3. 能够通过告警快速定位问题根因
4. 验证MTTR从小时级缩短到分钟级

## 五、告警机制

### 5.1 告警分级

| 级别 | 标识 | 响应时间 | 发送频率 | 场景 |
|------|------|---------|---------|------|
| **P0** | 🔴 | 立即 | 1分钟/次 | 节点宕机、核心服务不可用 |
| **P1** | 🔴 | 5分钟 | 10分钟/次 | CPU>80%、内存>85%、磁盘>90% |
| **P2** | 🟡 | 15分钟 | 30分钟/次 | CPU>50%、内存>70%、磁盘>75% |
| **P3** | 🔵 | 1小时 | 4小时/次 | 一般性提示信息 |

### 5.2 告警抑制

```yaml
inhibit_rules:
  # Critical 告警触发时，抑制同实例的 Warning 告警
  - source_match:
      severity: 'critical'
    target_match:
      severity: 'warning'
    equal: ['instance', 'alertname']
```

### 5.3 告警聚合

```yaml
route:
  group_by: ['alertname', 'severity', 'instance']
  group_wait: 10s      # 首次等待10秒聚合
  group_interval: 5m   # 同组告警间隔5分钟
  repeat_interval: 4h  # 重复告警间隔4小时
```

### 5.4 通知渠道

| 渠道 | 说明 | 配置 |
|------|------|------|
| **钉钉群** | 实时推送告警消息，支持 Markdown 格式 | 通过prometheus-webhook-dingtalk适配器 |
| **告警恢复** | 告警恢复时自动发送恢复通知 | Alertmanager自动配置 |

### 5.5 告警通知内容

告警通知包含以下信息：
- 告警级别和名称
- 告警实例和标签
- 当前指标值和阈值
- 告警持续时间
- 告警描述和建议
- 跳转链接（Grafana仪表盘、Prometheus查询、日志查询）
